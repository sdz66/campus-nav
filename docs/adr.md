# 架构决策记录（ADR）

> 每条决策记录背景、选项、结论与代价。变更决策必须新增条目而非修改历史。

---

## ADR-001 · Kafka 分区键 = hash(vin)

**背景**：50 万 msg/s 位姿流，下游需要"单车有序"（轨迹连续性是定位正确性底线），同时要求全局水平扩展。

**选项**：① 分区 = hash(vin)；② 分区 = hash(city)；③ 全局时间轮重排。

**结论**：①。单车所有消息进同一分区，天然有序且消费端无需重排；车际零关联，加分区即加并行度。

**代价**：终端扩容跨城市迁移时分区映射变化（归属 city 变化 = 换分区），需要双写过渡窗口；热点 vin（单终端高频 10Hz）远低于单分区容量，无热点风险。

## ADR-002 · 双队列分工：Kafka 数据流 + RocketMQ 指令流

**背景**：上行位姿是高吞吐追加流；下行指令要求事务性（落库与投递原子）、定向投递、延迟超时。单一队列两种诉求互相拖累。

**结论**：Kafka 承载上行数据流（吞吐优先）；RocketMQ 承载下行指令流（事务消息 + 5.x 定时消息秒级精度，替代租约轮询扫描）。

**代价**：两套 MQ 运维；指令回执（ACK）经 RocketMQ 回流，链路更长——用 trace_id 贯穿补偿可观测性。

---

## ADR-003 · 车端自治优先，云端镜像对账

**背景**：位置系统里"终端失联时位姿不可用"是致命的；网络不可靠是常态而非异常。

**选项**：① 云中心仲裁（车端纯采集）；② 车端自治仲裁 + 云端镜像对账。

**结论**：②。五态降级状态机在车端本地运行（断网闭环），同一状态机在 Flink 侧镜像；两端状态不一致时以云端为准触发指令（停车/遥控）。车端 SDK 缓存断网期数据，恢复后增量补传。

**代价**：同一状态机两份实现（车端 C++ / Flink Java），必须用同一份契约测试保证行为一致。

## ADR-004 · 单元化按城市 Set 化；分库分表键 = org_id

**背景**：99.99% 可用性 + 百万级扩展路径；业务查询永远带租户过滤。

**结论**：unit = city_code，单元内接入-消息-计算-存储全闭环，跨单元只同步元数据；关系库分片键 = org_id（1024 逻辑分片，16 库起步），组织/账户走全局单元。

**代价**：跨城市业务（全局报表）需要走全局单元聚合；设备 city 迁移需路由表双写过渡。

## ADR-005 · 状态/历史/业务三存储分离

**背景**：实时位姿（读写 50 Hz/终端）、轨迹（追加+时间范围扫描）、业务（事务+租户查询）三种读写模式截然不同。

**结论**：实时态 → Redis Cluster（60s TTL，唯一真相）；轨迹 → TDengine（列存 + TTL 90 天 + OSS 冷归档）；业务 → PostgreSQL 分库分表。

**代价**：三类存储的一致性靠 Flink 同源写入保证（同一 offset 点位），无跨库事务——业务上不需要。

## ADR-006 · 指令幂等 = 单调 seq + 租约定时消息

**背景**：指令链路"至少一次投递"必然产生重复；租约超时若用数据库轮询，10 万终端的扫描成本不可接受。

**结论**：下行指令带单车单调 `seq`，终端去重；派发租约用 RocketMQ 5 定时消息（30s 精确投递到超时检查），超时检查无状态可水平扩。

**代价**：seq 持久化在终端（重启不回退）；定时消息依赖 RocketMQ 5.x（4.x 的 18 级延迟不满足秒级任意定时）。

---

## ADR-007 · 坐标服务纯函数库 + 无状态服务双形态

**背景**：坐标转换在车端每条位姿都要用（不能走网络），在云端被规划/查询服务高频调用（要弹性）。

**结论**：同一算法实现两形态——车端内嵌 C++ 静态库（零网络开销），云端 gRPC 无状态服务（水平扩容）；两者由同一份契约测试（已知控制点往返 < 0.1 m）锁定行为一致。

**代价**：C++/Java(或 Python) 双语言实现同一算法；契约测试是唯一防漂移手段。

---

## ADR-008 · 契约全部版本化，先行于代码

**背景**：车端/云端/上游 BFF 三方并行开发，返工的最大来源是契约漂移。

**结论**：protobuf 包 `storm.nav.v1`、topic 后缀 `.v1`、Redis key 规范、REST 信封契约全部在 [contracts.md](contracts.md) 冻结后才允许写服务代码；升级走 `v2` 双写并行，禁止原地改语义。

**代价**：前期设计时间投入大（本仓库 docs/ 的存在理由）；双写期存储成本翻倍（临时性）。

---

## ADR-009 · 位姿链路时延预算分段治理

**背景**："端到端 P99 < 1s"作为单一指标无法定位劣化点。

**结论**：五段预算（车端→网关 100ms / 网关→Kafka 50ms / Kafka→Flink→Redis 300ms / 查询 50ms / 余量 500ms），每段独立 P99 指标与告警；任何一段超标即触发分段归因，不等用户感知。

**代价**：埋点与监控维度更多（OpenTelemetry span 全覆盖）。

---

## ADR-010 · 仿真与生产同构契约

**背景**：车端在 Gazebo 里开发、云端在本地 compose 里开发，环境差异是联调返工之源。

**结论**：本地开发栈（deploy/docker-compose.cloud.yml）与生产使用**同构中间件、同一套契约**，仅副本数/分区数不同；仿真回归门禁（5 路线 + 3 退化场景）进 CI。

**代价**：本地栈重（compose 全家桶），提供 `--profile lite` 最小集。
